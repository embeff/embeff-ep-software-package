# Service interface
The web-based service interface allows you
- Manage users and settings.
- Update your device.
- Generate a support file for service purposes.
- Manage the license.

To connect open a browser and type `http://<ep-serial-number or ip>`.

:information_source: Most of the functionality is restricted. Use the login button in the upper left corner to gain access.

![Web Interface (Not logged in)](img/Service_Info_NotLoggedIn.PNG)

# User management
All access to the ExecutionPlatform is restricted. There are normal users and administrators.

1. Users can:
- Run tests. The credentials are part of the [url](SoftwarePackage.md#use-software-package-to-write-and-run-tests) in the form _user:password@address_.
- Initiate and use [DUT Debugging](DUT-Debugging.md).
- View the active license.

2. Admins can:
- Do everything users can do.
- View and edit settings.
- Download support files and update the device.
- Add and remove users.

:information_source: Each device ships with a single default administrator user. You find the default credentials in the [factory settings](#factory-settings-and-reset).

To add or change users, you need to log in as an admin and open the User tab.

![User Management for Administrators](img/Service_UsersAdmin.PNG)

# Generate a support file
A support file is a package of log files captured on your device. This file will help us track down problems and provide you with a help.
Open the Services tab and click the `Generate support file` button point. The device will generate the package and your browser will download the support file.

Sent this file with a description of your problem to [support@embeff.com](mailto:support@embeff.com).

Information the support file contains:
- Device information such as serial number, version info, network settings and memory usage.
- Suite and Test names.
- Information which functions were called via `DUT Invoke`, their payload and return values.
- Any outputs (stdout) generated by your binaries.

The support file does __not__ contain:
- The binary files itself

In case you consider any of the things above sensitive, you may edit the support file before sending it to us. The generated support file is an unencrypted compressed file with plain text files. You may extract it with a tool such as [7-zip](https://www.7-zip.org).

# License
The active license determines which Endpoints can be used on the device. See [Prices and Packages](https://embeff.com/prices-and-packages) for an overview.

A license is valid for a single device and a given date range.
Code Interface and Analyzer Endpoint are always available. If the license expires, your [Configuration](https://ep-docs.embeff.com/#/EP_Config?id=configurations) is not allowed to use any other Endpoints. You can re-create your configurations at any time so it contains only the Endpoints your device is licensed for.

Licenses are stored in `.ep-license` files. To upload a new license, you need to log in as an admin and open the License tab. Reboot (Settings tab -> Reboot) the device to apply changes.

# System update
Open the Services tab and scroll down to the "Update" section. Drag the update file you received by us into the green area. The device will automatically initiate the update and restart afterwards.
The update may take up to 10 minutes. Do not power off your device during an update.

After a major or minor update the following steps are required to maintain compatibility with your new ExecutionPlatform version. A bugfix update needs no action. See [Version Compatibility](VersionCompatibility.md) for details.
- Download the new [software package](GettingStarted.md#downloads-in-customer-portal) from the [customer portal](https://customer.embeff.com) and update your local software package. At a minimum the contents of the `src` folder must be updated.
- [Re-create](EP_Config.md#creating-a-new-configuration) your `.ep-config.zip` files for the new version.

# Factory settings and reset
Factory settings are pre-configured values that are active when you receive your ExecutionPlatform.

Factory settings are defined as:
- Network settings
- User settings (default admin user)

You can view the factory settings in your customer portal:
1. Open https://customer.embeff.com/ and log-in.
2. Open the `Devices` tab and click on the ExecutionPlatform you are looking for.
3. The factory settings box displays information about the settings stored on the device.

To reset your ExecutionPlatform to use these factory settings:
1. Get physical access to the device.
2. Locate the reset button on the back plate of your device (between 24V DC and USB).
3. Press and hold the reset button for more than 5s.
4. The system led will change to red and the device will restart.
5. After the restart completes, the device will use the factory settings shown in the customer portal.

# Network settings
The device network is either configured automatically with a DHCP server (default) or manually with a static IP as requested by the customer.

Open the settings tab to change network related settings. Note that you need to reboot the device after you saved new settings.

:information_source: In case you misconfigured your device or its configuration is otherwise lost you can reset it to the [factory settings](#factory-settings-and-reset).

### Port usage
This table lists the ports that are required by the device for full feature use.

| Port | Direction | Mandatory | Description |
| --- | -----------| ------------- | ----------- |
| 80 (tcp) | User &#8594; Device | Yes | User authentication for tests. Webserver to control settings and access services. |
| 8270 (tcp) | User &#8594; Device | Yes | Robot Framework EP library communication. |
| 19020 (tcp) | User &#8594; Device | No | [Remote Debugging](DUT-Debugging.md).   |
