# Migrating to 9.8

9.8 changes how your project is set up. This page lists everything you need to adapt when you update from 9.7 or older, and walks you through it step by step:

- **embeff-ep replaces `EP.py`.** Your Robot Framework tests reach the ExecutionPlatform through a regular Python package, embeff-ep, which you install with pip. It replaces the files `app/EP.py` and `app/EP_common.py` of earlier Software Packages.
- **ep-configs are `.ep-config.zip` files.** The Customer Portal and the `ep-config` command line tool now produce `<name>.ep-config.zip` instead of `<name>.ep-config`. The same file works for Robot Framework, models and code completion, so the extra `.zip` copy some setups needed is gone.
- **ep-config names use `_` instead of `-`.** The Customer Portal now rejects names with `-`.

The [Release Notes](../ReleaseNotes.md) list all changes of 9.8.

## Why embeff-ep replaces EP.py

Until 9.7, the ExecutionPlatform client consisted of Python files inside the Software Package.
Your suites found them through a path, `${ep_app_dir}/EP.py`, and you installed the Python packages
they need by hand, in the versions our documentation named. Whenever a release needed other versions
of these packages, updating the Software Package was not enough: you also had to notice the change
and install the new versions yourself. Missed dependency updates were the most common cause of
problems after an update, and the tests failed with errors that did not point to the cause.

From 9.8, the client is a normal Python package that you install once per project:
```
pip install -r requirements.txt
```

What you get:

- **Dependencies can no longer cause problems.** embeff-ep declares the packages it needs and the versions it works with, and pip installs exactly those together with it. You no longer install or update `fastapi-websocket-rpc`, `websockets` or Robot Framework yourself, and an update can no longer leave them at a version that does not fit.
- **One line pins the version.** The `requirements.txt` of the Software Package names the embeff-ep version that matches your ExecutionPlatform. Updating means installing the new version; nothing to unzip, nothing to copy.
- **No more paths.** Robot Framework finds `EPLibrary` by name. No `${ep_app_dir}/EP.py` in every suite.
- **Works the same everywhere.** Your laptop, a colleague's laptop, a CI job, a Docker container: one `pip install` sets up all of them identically.
- **Transparent updates.** embeff-ep and the Software Package are public on GitHub ([embeff/embeff-ep](https://github.com/embeff/embeff-ep), [embeff/embeff-ep-software-package](https://github.com/embeff/embeff-ep-software-package)), one release per ExecutionPlatform version, under the Apache License 2.0. `git diff v9.8.0 v9.9.0` shows exactly what changed.

## What changes at a glance

| | Up to 9.7 | From 9.8 |
| --- | --- | --- |
| Installation | `pip install` of several packages by hand | `pip install -r requirements.txt` |
| ep-config file | `gpio.ep-config` | `gpio.ep-config.zip` |
| ep-config name | letters, digits, `_` and `-` | letters, digits and `_` |
| Robot Framework library | `Library    ${ep_app_dir}/EP.py    ${ep_url}    ${ep_binary_dir}/gpio.ep-config` | `Library    EPLibrary    ${ep_url}    ${ep_binary_dir}/gpio.ep-config.zip` |
| Keyword prefix in Robot logs | `EP.DUT Invoke` | `EPLibrary.DUT Invoke` |
| robotcode setting `ignoredLibraries` | `["EP"]` | `["EPLibrary"]` |
| Removed keywords | `GPIO Get Measurement Result In Ns`, `<SPIx> Read Minimal Clock Period In Ns`, `<SPIx> Read Maximal Clock Period In Ns` | `GPIO Get Measurement Result`, `<SPIx> Read Minimal Clock Period`, `<SPIx> Read Maximal Clock Period` with `ReturnType=ns` |
| System models | `self.AOUT.Set_Static(...)`, `self.UART2.on_byte_received(...)` | `self.AOUT.set_static(...)`, `self.UART2.on_bytes_received(...)` |
| App helpers (`cmake.resource`, `cmake_helper.py`, `bench/`, `gtest/`, `unity/`) | `app/` | unchanged, still in `app/` |

All other keywords, their arguments and the `robot.toml` variables stay as they are.

## Step by step

### 1. Update the Software Package and the ep-configs

Get the 9.8 Software Package from the [Customer Portal](https://customer.embeff.com) or from [GitHub](https://github.com/embeff/embeff-ep-software-package), as described in [Updating the Software Package](../SoftwarePackage.md#updating-the-software-package). Rebuild your DUT firmware with the new `src/`.

Build your ep-configs for 9.8 as for every minor update ([Version Compatibility](../VersionCompatibility.md)). The Customer Portal and the `ep-config` command line tool now write `<name>.ep-config.zip`. If a name contains `-`, the Customer Portal rejects it: replace `-` by `_`, here and wherever your suites and models use the name ([name rules](../EP_Config.md#creating-a-new-configuration)).

Delete the old `.ep-config` files, and the `.ep-config.zip` copies you made of them for code completion. If you copied the Software Package into your own repository, delete `app/EP.py` and `app/EP_common.py` there. Leftover copies are not used, but they confuse readers and editors.

### 2. Install embeff-ep

Run this command in the root folder of the Software Package:
```
pip install -r requirements.txt
```

Check the installation:
```
pip show embeff-ep
```
It should show `Version: 9.8.0`

`requirements.txt` also installs `robotcode`, the command line that runs Robot Framework suites with the settings of `robot.toml`. A robotcode installed in another environment does not see embeff-ep: run the one from this environment.

### 3. Robot Framework suites

Replace the path of `EP.py` by the library name `EPLibrary` in every `.robot` and `.resource` file, and add `.zip` to the ep-config file name:

```robotframework
*** Settings ***
# Before
Library    ${ep_app_dir}/EP.py    ${ep_url}    ${ep_binary_dir}/gpio.ep-config
# After
Library    EPLibrary    ${ep_url}    ${ep_binary_dir}/gpio.ep-config.zip
```

In VS Code, use **Replace in Files** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>H</kbd>): search `${ep_app_dir}/EP.py`, replace with `EPLibrary`, files to include `*.robot, *.resource`. If your suites reach `EP.py` through another path, for example `${CURDIR}/../ep/app/EP.py`, replace that path the same way. Then search `.ep-config` and add `.zip` where it ends the file name.

On Linux and macOS, or in a CI script, the same replacement:
```
grep -rlF --include='*.robot' --include='*.resource' '${ep_app_dir}/EP.py' . | xargs sed -i 's|${ep_app_dir}/EP\.py|EPLibrary|; s|\.ep-config\([[:space:]]\)|.ep-config.zip\1|g; s|\.ep-config$|.ep-config.zip|'
```

Then:
- In `.vscode/settings.json`, change `"robotcode.analysis.cache.ignoredLibraries": ["EP"]` to `["EPLibrary"]`.
- Keep `ep_app_dir` in `robot.toml`: the `Resource ${ep_app_dir}/cmake.resource` lines and the other app helpers still use it.
- If a suite calls a keyword with the library prefix, such as `EP.DUT Invoke`, change it to `EPLibrary.DUT Invoke`. Without a prefix, nothing changes. If you prefer the short name, import the library with an alias: `Library    EPLibrary    ${ep_url}    ${ep_binary_dir}/gpio.ep-config.zip    AS    EP`.

### 4. Removed keywords

Replace the keywords removed in 9.8 by their successors with the argument `ReturnType=ns`:

| Removed | Use instead |
| --- | --- |
| `GPIO Get Measurement Result In Ns` | `GPIO Get Measurement Result    ReturnType=ns` |
| `<SPIx> Read Minimal Clock Period In Ns` | `<SPIx> Read Minimal Clock Period    ReturnType=ns` |
| `<SPIx> Read Maximal Clock Period In Ns` | `<SPIx> Read Maximal Clock Period    ReturnType=ns` |

### 5. System models

Skip this step if you do not use the [System Endpoint](../Endpoints/System.md).

Models are Python code and therefore case-sensitive. Call endpoint functions in snake case, for example `set_static` and `reset` of the [Analog-Out Endpoint](../Endpoints/Analog-Out.md) instead of `Set_Static` and `Reset`. In Robot Framework suites nothing changes, because Robot Framework ignores case, spaces and underscores in keyword names.

The UART callback `on_byte_received` is now `on_bytes_received`. It receives a `bytes` object with one or more bytes instead of one `int` per byte ([UART callbacks](../Endpoints/UART.md#callbacks)):
```python
# Before: called once per byte with an int
def data_received(self, value):
    self.outputs["data_buffer"].append(value)
...
self.UART2.on_byte_received(self.data_received)

# After: called with bytes holding one or more bytes
def data_received(self, data):
    self.outputs["data_buffer"].extend(data)
...
self.UART2.on_bytes_received(self.data_received)
```

If a model imports its ep-config with `import <name> as config` and the name contained `-`, use the new name with `_` (step 1).

### 6. CI pipelines

Add the installation before the test step, in the environment the tests run in:
```
pip install -r requirements.txt
```
A CI job that only runs tests and does not build firmware can install embeff-ep without the Software Package:
```
pip install "embeff-ep[robot] @ git+https://github.com/embeff/embeff-ep@v9.8.0"
```

### 7. Check the result

From the root folder of the Software Package, with the environment of step 2 active:
```
robotcode robot --dryrun example/hello_world/hello_world.robot
```
`--dryrun` stops at the connection if your EP is not reachable, which is fine: the library was found. Then run your suites as usual.

## Troubleshooting

| Message | Cause | Fix |
| --- | --- | --- |
| `Library '.../app/EP.py' does not exist.` | A suite still loads the old path. | Step 3. |
| `Importing library 'EPLibrary' failed: ModuleNotFoundError: No module named 'EPLibrary'` | embeff-ep is not installed in the environment that runs the tests. | Step 2; in VS Code select the interpreter of that environment. |
| `Importing library 'EPLibrary' failed` although `pip show embeff-ep` finds it, and the `PYTHONPATH` printed below the message belongs to another environment | `robotcode` comes from another installation, which runs a Python without embeff-ep. | Run the robotcode of the environment of step 2; `pip install -r requirements.txt` installs it there. |
| The ep-config file is not found | The suite still names `.ep-config` instead of `.ep-config.zip`. | Step 3. |
| `No keyword with name 'GPIO Get Measurement Result In Ns' found.` | The suite uses a removed keyword. | Step 4. |
| `AttributeError` naming `Set_Static`, `Reset` or `on_byte_received` in a model | The model uses the old names. | Step 5. |
| `pip show embeff-ep` shows another version than your Software Package | An older installation in the same environment. | `pip install -r requirements.txt` again, in that environment. |
